# Assignment GLS 1.0 — Detailed Analysis

## 1. Assignment Overview

This assignment covers three connected stages of the ASIC digital-design flow:

1. **Synthesis**
2. **Gate-Level Simulation (GLS)**
3. **Power Analysis**

The assignment specifically targets the **Adder** configuration of `alu8_top`, performs GLS using the synthesized gate-level netlist plus SDF timing information, dumps `Adder.vcd`, and then uses that switching activity in **PrimeTime** to estimate dynamic power.

> Source-grounded note: the assignment is only two pages, so this document preserves every explicit requirement and expands the concepts without inventing project-specific numerical results or missing commands.

# 13. Dynamic Power

The assignment specifically asks for dynamic power.

A useful conceptual relationship is:

```text
P_dynamic ∝ α × C × V² × f
```

where:

- `α` = switching activity
- `C` = effective capacitance
- `V` = supply voltage
- `f` = switching frequency

The important point for this assignment is that **the VCD provides switching activity information**.

No numerical voltage, frequency, capacitance, or power values are specified in the assignment, so actual values must come from the project/library/PrimeTime run.

# 28. Final Summary

The assignment implements a **post-synthesis verification and power-analysis flow** for the Adder.

The required sequence is:

1. Set the generate variable in `alu8_top.v` to `0`.
2. Synthesize the Adder configuration.
3. Generate the gate-level netlist, SDC, and SDF.
4. Disable multiplier testcases.
5. Enable Adder testcases.
6. Dump `Adder.vcd`.
7. Run GLS in QuestaSim using the netlist, SDF, testbench, and `Lib.v`.
8. Document successful GLS with a waveform and results log.
9. Run PrimeTime power analysis using the VCD and required design files.
10. Produce `Adder_Power.rpt`.
11. Submit all specified synthesis outputs and reports.

## Core Concept

> **Synthesis creates the gate-level implementation → GLS verifies that implementation with timing information → VCD captures switching activity → PrimeTime uses that switching activity to estimate dynamic power.**
